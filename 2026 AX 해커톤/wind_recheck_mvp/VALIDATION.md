AIStream 실제 API는 `/jntp-gpu/SV-e434a471/predict/wind`에 multipart `file`로 호출했습니다. classes는 목록이며 검출 결과는 defects입니다. confidence는 제공되지 않습니다. defects가 빈 배열이면 후처리 미검출이며 무결함 보증이 아닙니다. 오류·해석 불가 응답은 정상 후보에서 제외합니다. 모델 입력은 전체 해상도를 유지한 RGB JPEG quality=90 정규화 이미지입니다. 원본 바이트 그대로의 평가라고 주장하지 않습니다.

## 재검수 결과

TEST의 미검출 후보 4장 중 실제 누락 결함은 2장입니다. 비교는 동일한 후보와 K에서 수행했습니다. 검토 완료 여부와 무관하게 고정된 평가 표본을 사용합니다.

| 방법 | K | 포착/누락 | Capture@K | Precision@K | Remaining@K |
|---|---:|---:|---:|---:|---:|
| 고정 seed 무작위 | 1 | 1/2 | 50% | 100% | 1 |
| 영상 품질 규칙 / 현재 Wind Recheck | 1 | 0/2 | 0% | 0% | 2 |
| 고정 seed 무작위 | 3 | 2/2 | 100% | 66.67% | 0 |
| 영상 품질 규칙 / 현재 Wind Recheck | 3 | 1/2 | 50% | 33.33% | 1 |
| 모든 방법 | 4 | 2/2 | 100% | 50% | 0 |

균등 무작위의 Capture 기대값은 K=1에서 25%, K=3에서 75%입니다. 고정 seed 1회 무작위 결과를 일반적인 무작위 성능으로 단정하지 않습니다. 현재 규칙은 이 시험에서 기대값보다도 낮았습니다. 전량 검수의 100%는 개선 성과가 아닙니다. Capture는 선택된 정답 결함 수이며 사람의 실제 발견률을 측정하지 않았습니다.

학습 후보 17건 중 누락 결함이 2건뿐이어서 사전에 정한 양성 최소 3건에 미달했습니다. 학습형 순위 모델 파일은 생성하지 않았습니다. 현행 우선순위는 영상 품질 규칙이며 결함 확률·위험도 보정 또는 성능 우위를 입증하지 못했습니다.

재현 스크립트는 `scripts/run_validation_experiment.py`, `scripts/expand_training.py`, `scripts/finalize_experiment.py`입니다. 집계 수치와 앱 소스 SHA256은 `reports/final_metrics.json`에 있습니다. 전체 표본 매핑은 서버에 별도 보관합니다.

## 부분 재분석 평가 기준

1. **평가 표본.** 허용된 실제 이미지와 정답 JSON을 일대일로 연결합니다. 새 검증에서는 장소·날짜 그룹과 중복 이미지를 분리하고, 평가 표본과 전처리·겹침·검수 예산 K를 결과를 보기 전에 고정합니다. 제공 모델의 학습 자료와 중복되는지 확인할 수 없다면 그 한계를 명시합니다.
2. **전체 미검출과 재검수 후보.** AIStream 전체 요청이 성공하고 `defects=[]`일 때만 미검출로 분류합니다. 그중 4개 영역의 응답을 모두 해석할 수 있고 한 영역 이상에서 검출되면 이미지 한 장을 후보로 셉니다. 실제 운영 중 일부 영역의 검출만 확인된 건은 사람에게 보류 또는 확인 대상으로 보여줄 수 있으며, 성능 비교에는 4개 영역 완료 건만 포함합니다. 전체 오류와 부분 미완료는 각각 별도로 집계하고, 전체 대상 대비 평가에 포함된 수를 함께 표시합니다.
3. **이미지 단위 포착.** K개 선택 이미지 중 원본 정답에 결함이 있는 수를 포착 수로 집계합니다. Capture@K는 포착 수 ÷ 평가 대상의 전체 누락 결함 수, Precision@K는 포착 수 ÷ 실제 선택 수, Remaining@K는 전체 누락 결함 수 − 포착 수입니다. 누락 결함이 0건이면 Capture@K는 평가 불가입니다.
4. **위치 단위 재검출.** 부분 예측 박스를 원본 좌표로 변환해 정답 박스와 대조합니다. 팀 평가에서 박스 IoU 0.50 이상인 쌍이 있는 경우를 위치 일치로 집계하고, IoU 0.10은 참고값으로만 보고합니다. 클래스 일치나 세그멘테이션 품질은 별도로 검증해야 합니다.
5. **개선 판정.** 같은 이미지와 같은 K에서 부분 검출 우선 방식, 기존 규칙, 균등 무작위를 비교합니다. 무작위 기대 Capture@K는 누락 결함이 있는 경우 K ÷ 평가 대상 수입니다. 고정한 K에서 제안 방식이 기존 규칙과 무작위 기대값을 모두 넘을 때만 해당 표본의 관측 개선으로 표시합니다. 일반화된 성능 개선 주장은 독립 표본 재검증 후 판단합니다. 추가 API 호출 수와 응답 시간은 성능 지표와 함께 보고합니다.

### 첨부 Validation 200장 탐색 실험

팀원이 제공한 `results.csv`, `candidates.csv`, 결과보고서의 이미지 단위 집계를 대조했습니다. 전체 성공 196장과 오류 4장으로, 오류 4장은 모두 실제 결함 이미지였습니다. 전체 성공 건 중 36장이 미검출이었고 이 중 실제 결함은 10장이었습니다. 해당 36장 모두 부분 분석을 완료했습니다.

| 동일한 미검출 36장, K=8 | 포착 수 | Capture@8 | Precision@8 | Remaining@8 |
|---|---:|---:|---:|---:|
| 부분 재분석 후보 | 1 | 10.0% | 12.5% | 9 |
| 균등 무작위 기대값 | 2.22 | 22.2% | 27.8% | 7.78 |

첨부 CSV에는 기존 품질 규칙 점수가 없어 이 표본의 규칙 대비 성능은 계산할 수 없습니다. 무작위 기대값보다 낮으므로 개선 판정 기준을 충족하지 못했습니다. 실제 결함이 있는 후보 한 장의 최대 박스 IoU는 0.0264이며, 위치 일치로 집계된 사례는 0장입니다. 부분 요청은 144개 입력이 최종 성공했습니다.

이 실험은 인접 영역 겹침 20%를 사용했습니다. 현재 배포 웹의 영역 겹침은 약 10%이므로 웹 설정의 성능은 별도 재검증이 필요합니다. 위 판정 기준은 결과 해석과 후속 검증에 적용하며, 이미 완료된 실험의 사전 등록 기준으로 간주하지 않습니다.

## AgentStream

9팀의 기존 qwen3.5-122b 모델로 전용 비공개 챗봇을 생성했습니다. 입력 메모 4문장의 관찰·불확실성·후속 요청·담당자 분류 JSON 응답을 실제 채팅 화면에서 확인했습니다. 이는 기능 확인 1예이며 정확도·업무 효율 검증이 아닙니다. 최초 JSON 단독 입력에는 설명문이 반환되어 고정된 분류 요청문이 필요함도 확인했습니다. 목록·큐에는 320×240 이하 미리보기를 사용하고 확대 검토와 추론 입력은 전체 해상도를 유지합니다.

서버는 LLM이 원문을 생성하게 하지 않고 문장 번호와 허용 태그만 검증한 뒤 원문에서 문장을 복원하도록 준비했습니다. 9팀 워크스페이스의 API Key 발급 완료를 확인했습니다. 기존 member 계정은 키 발급 권한이 없으며 사용자가 발급받은 키를 서버 비밀 설정에 등록했습니다. 사용자 승인으로 전용 챗봇을 공개하고 CHAT_INVOKE 권한 매핑을 저장했습니다. 서버·검토 UI 연동 코드는 작성·배포했으며 모의 스트림과 세션 격리·원문 변경 방지 검사를 통과했습니다. 실제 외부 API 상태 healthy, 세션 생성 HTTP 201, NDJSON 정상 완료를 대회 서버에서 확인했습니다. 합성 메모 4문장에서 사전 예상 태그와 4개가 일치했으며 단일 기능 점검이지 정확도 벤치마크가 아닙니다. 실제 스트림은 event가 프로토콜 이벤트명, type은 메시지 종류이므로 event를 우선 해석하도록 수정하고 회귀 테스트를 추가했습니다. 공개 웹에서도 분류·수동 보류 저장·재조회·원복을 확인했습니다. 웹 점검에서 합성 메모 안내 문장도 관찰로 분류되어 의미 오분류 가능성을 확인했습니다. 자동 확정 없이 검토자가 확인해야 합니다.
